## 1. 프로젝트 개요

격자 무늬가 인쇄된 원판형 웨이퍼를 카메라로 촬영하고, Python / OpenCV로 점·선 형태의 추가 결함을 검출한 뒤 검사 결과에 따라 정상 웨이퍼와 불량 웨이퍼를 자동 분류하는 시스템을 구현했습니다.

검사 결과를 PC 화면에 표시하는 데 그치지 않고, MC Protocol을 통해 Mitsubishi PLC에 전달하여 실제 설비의 후속 동작 기준으로 활용했습니다. 결함이 기준 범위 이내인 웨이퍼는 컨베이어를 통해 스토퍼 위치까지 이송한 뒤 HCR-3A 협동로봇의 작업 요청 신호를 전달해 창고에 적재하고, 결함 기준을 초과한 웨이퍼는 배출 실린더를 동작시켜 분리하도록 구성했습니다.

프로젝트에서 제가 담당한 핵심은 **비전 검사 결과가 PLC의 유효한 제어 데이터로 전달되도록 통신 흐름을 구성하고, PLC 시퀀스와 로봇 Digital I/O를 연결해 반복 운전이 가능하도록 만드는 것**이었습니다.

## 3. 주요 구현 내용

### 3-1. OpenCV 기반 웨이퍼 위치 및 촬영 자세 보정

카메라와 웨이퍼 사이의 거리나 촬영 각도가 달라져도 검사할 수 있도록 화면 중앙의 고정 영역만 검사하는 방식에서 벗어나 **전체 프레임에서 원판 후보를 탐색**하도록 구성했습니다.

기존 도안은 촬영 거리가 멀어지면 격자 크기와 두께가 작아져 방향을 안정적으로 인식하기 어려웠습니다. 이를 개선하기 위해 격자의 크기와 두께를 키운 웨이퍼 도안을 다시 제작하고, 영상 처리 단계에서도 원판의 위치와 기울기를 보정했습니다.

주요 처리 과정은 다음과 같습니다.

1. 여러 밝기 임계값과 Canny Edge를 이용해 원판 윤곽 후보 탐색
2. `fitEllipse`를 이용한 타원 형상 추정
3. 타원의 장축·단축을 이용한 타원→원 Affine 보정
4. `HoughLinesP`를 이용한 격자 방향 검출
5. 격자의 90° 반복 대칭을 고려한 회전 후보 비교
6. `findTransformECC`와 Homography를 이용한 다중 해상도 영상 정합

```text
Camera Frame
    ↓
전체 화면 원판 후보 탐색
    ↓
Ellipse Fitting
    ↓
타원 → 원 Affine 보정
    ↓
Hough Line 기반 격자 각도 계산
    ↓
0° / 90° / 180° / 270° 후보 비교
    ↓
128 → 256 → 512 다중 해상도 정합
    ↓
기준 정상 영상에 정렬
```

### 3-2. 정상 격자를 제외한 점·선 형태 결함 검출

정상 웨이퍼 영상을 기준 이미지로 등록하고, 촬영한 검사 영상을 기준 이미지에 정합한 뒤 정상 격자에는 존재하지 않는 추가 어두운 영역을 결함 후보로 추출했습니다.

정상 격자 주변이 결함으로 잘못 검출되는 현상을 줄이기 위해 격자 주변 영역을 제외하고, 남은 어두운 픽셀에는 Morphological Closing을 적용했습니다. 이 과정으로 정상 격자에 의해 끊겨 보이는 선 형태의 결함 후보를 연결한 뒤 `connectedComponentsWithStats`로 연결 영역을 분리해 개수를 계산했습니다.

```text
정상 기준 영상과 검사 영상 정합
        ↓
밝기 정규화 및 차영상 계산
        ↓
정상 격자 주변 영역 제외
        ↓
추가 어두운 영역 추출
        ↓
Morphological Closing
        ↓
Connected Component 분석
        ↓
결함 개수 산출
```

- 검사 범위: 원판 중심 기준 반지름의 약 82% 내부
- 결함 면적 기준: 카메라 영상 기준 160 px 이상
- 판정 방식: 추가된 어두운 연결 영역 한 덩어리를 결함 1개로 계산

서로 붙어 있거나 매우 가까운 결함은 하나로 연결되어 검출될 수 있으며, 정상 격자선에 완전히 가려진 결함은 영상만으로 구분하기 어렵다는 한계도 함께 고려했습니다.

### 3-3. PLC 요청 기반 카메라 촬영 및 MC Protocol 통신

PLC가 검사 요청을 발생시키면 PC가 이를 확인하고 카메라에서 새로운 프레임을 취득해 검사하도록 구성했습니다. PLC 요청 신호가 들어오기 전에는 PC의 수동 검사 기능이 동작하지 않도록 구분했습니다.

PLC의 `M11` 신호가 OFF에서 ON으로 바뀌면 새로운 요청 번호를 생성해 `D120`에 기록하고, PC는 `D120`과 운전 허가 `D121`을 확인한 뒤 검사를 시작합니다. 이전 프레임이 검사에 사용되지 않도록 요청 후 약 0.3초의 안정화 시간을 두고 새 프레임을 취득하도록 했습니다.

PC와 PLC 간 데이터 송수신은 초기 Modbus TCP 방식에서 데이터 길이 처리 문제를 확인한 뒤 **MC Protocol 3E Binary / TCP** 방식으로 전환했습니다.

#### 주요 디바이스 구성

| Device | 방향 | 기능 |
|---|---|---|
| D100 | PC → PLC | PC 검사 상태 |
| D101 | PC → PLC | 접수한 요청 번호 |
| D102 | PC → PLC | 검사 완료 확정 번호 |
| D103 | PC → PLC | 검사 판정 결과 |
| D104 | PC → PLC | 검사 오류 코드 |
| D105 | PC → PLC | 통신 하트비트 |
| D106 | PC → PLC | PC 프로그램 실행 구분 번호 |
| D107 | PC → PLC | 결함 개수 |
| D120 | PLC → PC | 검사 요청 번호 |
| D121 | PLC → PC | 검사 운전 허가 |
| D140~D142 | PLC 내부 | 검증된 판정·완료 번호·결함 개수 |

PC는 검사 상태와 결과 데이터를 먼저 기록하고 완료 번호를 마지막에 기록하도록 구성했습니다. PLC는 요청 번호와 완료 번호의 일치 여부, 오류 상태, 판정 결과와 결함 개수의 유효성을 확인한 뒤에만 검사 결과를 내부 데이터로 보관하도록 했습니다.

하트비트 중단, 검사 시간 초과, 완료 번호 불일치 또는 비정상 데이터가 발생하면 오류 보류 상태로 전환해 이전 검사 결과로 설비가 동작하지 않도록 했습니다.

### 3-4. 결함 개수에 따른 PLC 자동 분기 시퀀스

PLC에서 유효한 결함 개수를 확인한 뒤 정상 웨이퍼와 불량 웨이퍼의 후속 동작을 분기했습니다.

| 판정 신호 | 결함 개수 | 후속 동작 |
|---|---:|---|
| M60 | 0~3개 | 스토퍼 위치까지 이송 후 협동로봇 적재 요청 |
| M61 | 4~100개 | 배출 실린더 동작 |
| M62 / M63 | 분기 이벤트 | 각 분기 시점의 1 Scan 동작 요청 Pulse |

공급·가공·분배 실린더와 컨베이어는 다음 순서로 동작하도록 PLC 시퀀스를 구성했습니다.

```text
모든 실린더 후진 위치 확인
        ↓
로봇에 소재 공급 요청
        ↓
공급 실린더 전진 / 후진
        ↓
가공 실린더 전진
        ↓
약 10초 유지 후 후진
        ↓
분배 실린더 전진 / 후진
        ↓
컨베이어 약 0.2초 구동
        ↓
카메라 촬영 위치 정지
        ↓
비전 검사 결과 수신 및 검증
        ↓
정상 / 불량 분기
```

불량 웨이퍼는 결함 개수 기준에 따라 배출 실린더를 동작시켰습니다. 정상 웨이퍼는 스토퍼 센서가 감지될 때까지 컨베이어로 이송한 뒤 로봇 작업 요청 신호를 전달하도록 구성했습니다.

### 3-5. NPN PLC와 PNP 협동로봇 간 Relay 기반 Digital I/O 직접 배선

Mitsubishi PLC는 NPN 방식, Hanwha Robotics HCR-3A는 PNP 방식으로 서로 다른 디지털 신호 방식을 사용했습니다. 두 장치의 출력 신호를 직접 연결하는 방식으로는 원하는 신호 연동을 구성하기 어려워 **Relay를 이용해 PLC와 로봇 사이의 Digital I/O 인터페이스를 구성하고 직접 배선**했습니다.

이 과정에서 Relay 접점을 이용해 서로 다른 신호 방식의 제어 신호가 연동되도록 회로를 구성하고, PLC 출력과 로봇 입력 간 신호 전달 관계를 확인했습니다.

주요 수행 내용은 다음과 같습니다.

- NPN PLC와 PNP 협동로봇의 출력 신호 방식 차이 확인
- PLC와 로봇 간 신호 연동을 위한 Relay 회로 구성
- Relay 접점 및 코일 단자 확인
- NPN PLC 측과 PNP 로봇 측 신호선 직접 배선
- PLC 출력에 따른 Relay 동작 및 로봇 Digital Input 신호 확인
- PLC 시퀀스와 로봇 작업 요청 신호 연동

### 3-6. PLC 출력 기반 협동로봇 작업 요청 및 반복 운전 시퀀스

로봇 내부 프로그램을 직접 작성하거나 티칭한 것이 아니라, **PLC에서 로봇의 작업 요청 신호를 생성하고 Relay Digital I/O를 통해 로봇과 연동하는 제어 흐름**을 담당했습니다. 로봇 내부 동작 프로그램 및 티칭은 팀원이 담당했습니다.

PLC에서는 정상 판정 웨이퍼가 스토퍼 위치에 도달했는지 확인한 뒤 로봇에 적재 작업을 요청하도록 구성했습니다.

주요 신호 흐름은 다음과 같습니다.

```text
정상 판정 M60
      +
스토퍼 센서 X13
        ↓
내부 상태 M25 ON
        ↓
PLC 출력 Y39
        ↓
Relay Digital I/O
        ↓
HCR-3A 로봇 적재 작업 요청
```

적재 위치를 구분하기 위해 `M25`가 성립할 때 카운터 `C0 K2`를 계수하도록 구성했습니다. 두 번째 적재 조건에서 `C0` 접점이 ON되면 `Y3A`를 함께 출력해 기존 적재 위치의 왼쪽 자리에 적재하도록 로봇에 추가 신호를 전달했습니다.

로봇 동작 상태 `M0`가 성립하면 `Y38`을 출력해 다음 소재 공급 단계로 이어지도록 구성했습니다.

### 3-7. 반복 운전을 위한 초기화 및 실린더 Interlock

자동 운전에서는 한 사이클에서 사용한 요청 신호나 출력 상태가 다음 사이클까지 남아 있으면 중복 동작 또는 시퀀스 정지가 발생할 수 있습니다. 이를 방지하기 위해 요청 신호의 발생·완료·초기화 조건을 구분하고, 실린더 전진·후진 출력이 동시에 성립하지 않도록 상호 Interlock을 구성했습니다.

- 검사 요청 신호를 상승 Pulse로 변환해 사이클마다 1회 발생
- 요청 번호와 완료 번호를 비교해 이전 결과와 새 결과 구분
- 검사 완료 후 요청 번호 초기화 및 다음 요청 대기
- 실린더 전진·후진 명령을 별도 상태 신호로 분리
- 전진 조건에는 후진 신호의 NC 접점, 후진 조건에는 전진 신호의 NC 접점을 적용
- 동작 완료 조건에서 해당 상태를 해제하도록 SET/RST 조건 수정

이를 통해 검사 요청, 판정, 적재·배출, 초기화가 연결되는 반복 운전 구조를 구성했습니다.

## 4. 주요 트러블슈팅

### Trouble 01. 촬영 거리와 각도 변화로 웨이퍼 및 격자를 인식하지 못하는 문제

**Problem**

카메라와 웨이퍼 사이의 거리가 멀어지면서 기존 격자가 영상에서 작고 얇게 표현되어 격자 방향을 안정적으로 찾지 못했습니다. 웨이퍼가 화면 중앙에서 벗어나거나 카메라가 비스듬한 경우에는 고정된 중앙 검사 범위를 벗어나는 문제도 발생했습니다.

**Analysis**

검사 실패가 결함 판정 단계보다 앞선 원판 위치 탐색과 격자 정합 단계에서 발생한다는 점을 확인했습니다. 촬영 각도에 따라 원형 웨이퍼가 타원처럼 보이고, 격자의 90° 대칭 때문에 한 방향만으로는 정합 방향을 결정하기 어려웠습니다.

**Solution**

- 격자의 크기와 두께를 키운 웨이퍼 도안 재제작
- 중앙 고정 검사 범위를 제거하고 전체 프레임에서 원판 후보 탐색
- Ellipse Fitting 후 타원→원 Affine 보정
- Hough Line으로 격자 대표 각도 계산
- 4개의 90° 회전 후보 비교 및 다중 해상도 Homography 정합
- 정합 상관값이 기준 0.75 미만이면 오판정 대신 재촬영 처리

**Result**

원판의 위치와 촬영 각도가 달라져도 외곽과 격자를 기준 영상에 맞출 수 있는 검사 구조를 구성했습니다.

### Trouble 02. Modbus TCP 데이터 길이 처리 문제

**Problem**

초기에는 Modbus TCP로 비전 프로그램과 PLC 사이의 데이터 송수신을 구현했지만, 응답 데이터 길이를 정확하게 처리하지 못해 검사 데이터가 원하는 형태로 전달되지 않았습니다.

**Analysis**

TCP 연결 자체의 문제가 아니라 응답 프레임의 데이터 길이와 프로그램이 예상한 길이가 일치하지 않는 문제로 판단했습니다.

**Solution**

기존에 사용 경험이 있던 MC Protocol 3E Binary 방식으로 전환했습니다.

- PLC Ethernet Open Setting을 TCP / MC Protocol / Binary / Port 1387로 구성
- PC가 PLC D 디바이스를 직접 읽고 쓰는 구조로 변경
- 응답 헤더, 데이터 길이 및 MC 종료 코드를 매 요청마다 검증
- 요청 번호와 완료 번호를 분리하고 완료 번호를 마지막에 기록
- 읽기·쓰기, 분할 응답, 오류 응답, 재연결 및 시간 초과를 포함한 단위시험 수행

**Result**

MC 통신 코드의 단위시험 10개가 모두 통과했으며, 검사 상태·판정·오류·결함 개수를 PLC D 레지스터에 전달하는 구조를 완성했습니다.

### Trouble 03. 검사 요청 신호가 초기화되지 않아 다음 촬영이 불가능한 문제

**Problem**

첫 검사에서 요청 신호를 만드는 내부 M 접점이 SET된 뒤 RESET되지 않아 다음 웨이퍼에서 새로운 상승 Edge가 발생하지 않았습니다.

**Analysis**

연속 운전에서는 검사 요청이 단순 유지 신호가 아니라 사이클마다 새롭게 발생하는 이벤트여야 합니다. 이전 요청 상태가 남아 있으면 다음 제품의 촬영 요청을 만들 수 없었습니다.

**Solution**

- 요청 신호를 상승 Pulse로 변환
- 요청마다 새로운 요청 번호 생성
- PLC 요청 번호와 PC 접수·완료 번호가 일치할 때만 결과 수용
- 결과 확인 후 요청 번호를 초기화해 재동기화
- 다음 검사 전에 요청용 내부 M 접점의 SET/RST 조건 수정

**Result**

첫 검사 이후에도 요청 상태가 정상적으로 초기화되어 다음 웨이퍼가 독립적인 요청 번호로 촬영·검사될 수 있도록 반복 사이클을 구성했습니다.

### Trouble 04. 배출 실린더 전진·후진 출력 충돌

**Problem**

배출 실린더의 전진 신호가 계속 유지되어 후진 중에도 다시 전진하는 오동작이 발생했습니다.

**Analysis**

전진과 후진을 하나의 연속 흐름으로 작성해 상반되는 명령이 동시에 성립할 수 있었고, 한 동작이 끝난 뒤 전진 조건이 명확히 해제되지 않았습니다.

**Solution**

- 전진 명령과 후진 명령을 별도 상태 신호로 분리
- 전진 조건에 후진 신호 NC 접점 적용
- 후진 조건에 전진 신호 NC 접점 적용
- 양쪽 출력이 동시에 켜지지 않도록 상호 Interlock 구성
- 각 동작 완료 조건에서 해당 상태를 해제하도록 SET/RST 수정

**Result**

후진 중 재전진하는 현상을 방지하고, 한 방향 동작을 완료한 뒤에만 반대 방향으로 전환되도록 수정했습니다.

### Trouble 05. 컨베이어 시작·정지 타이밍이 공정 상태와 맞지 않는 문제

**Problem**

소재 공급 직후 촬영 위치까지 이동하는 동작, 촬영 후 분기 이송, 각 분기 완료 후 정지가 서로 다른 시점에 필요해 단일 운전 조건만으로는 컨베이어가 원하는 위치에서 멈추지 않았습니다.

**Analysis**

초기 위치 이동, 검사 대기, 검사 결과에 따른 후속 이송, 스토퍼 도착 및 배출 완료라는 공정 상태를 구분하지 않으면 컨베이어 시작·종료 시점을 정확히 제어하기 어려웠습니다.

**Solution**

- 공급 완료 후 약 0.2초 구동해 카메라 촬영 위치로 이동
- 촬영 중에는 정지 상태 유지
- 유효한 검사 결과인 M60 또는 M61에 따라 후속 이송 재개
- 분기 동작의 완료 센서와 상태 신호를 조합
- 배출 또는 스토퍼 도착 완료 시 컨베이어 정지 및 다음 사이클로 전환

**Result**

컨베이어가 공정 단계별로 필요한 구간에서만 동작하고, 촬영 및 후속 처리 완료 시점에 멈추도록 시퀀스를 분리했습니다.

## 6. 회고 및 배운 점

이번 프로젝트를 통해 비전검사는 이미지를 분석하는 프로그램만 완성한다고 끝나는 것이 아니라, 촬영 조건을 안정화하고 검사 결과의 유효성을 판단한 뒤 PLC가 사용할 수 있는 형태로 전달해 실제 설비 동작까지 연결해야 한다는 점을 경험했습니다.

촬영 거리와 각도가 달라져 기존 격자가 인식되지 않는 문제를 해결하면서 웨이퍼 도안 개선과 영상 보정을 함께 적용했습니다. 통신 과정에서는 연결 성공과 데이터 전달 성공이 서로 다른 문제라는 점을 확인했고, MC Protocol로 전환한 뒤 요청 번호·완료 번호·오류 상태를 정의해 PC와 PLC가 동일한 검사 사이클을 인식하도록 구성했습니다.

또한 NPN PLC와 PNP 협동로봇의 신호 방식 차이를 Relay 회로와 직접 배선으로 연결하면서, 소프트웨어의 제어 명령이 실제 전기 신호와 장비 동작으로 이어지려면 전기적 인터페이스까지 이해해야 한다는 점을 배웠습니다.

PLC 시퀀스 디버깅에서는 요청 신호 초기화, 실린더 전진·후진 충돌, 컨베이어 시작·종료 조건을 수정했습니다. 이를 통해 연속 자동 운전의 안정성은 개별 명령보다 **신호의 발생·유지·완료·초기화 조건과 장치 간 인터록을 전체 흐름에서 설계하는 것**에 달려 있음을 확인했습니다.

```text
Camera
  ↓
OpenCV Vision Inspection
  ↓
MC Protocol Communication
  ↓
Mitsubishi PLC Sequence
  ↓
Relay Digital I/O
  ↓
HCR-3A Robot / Cylinder / Conveyor
  ↓
Cycle Reset & Next Wafer
```

이 경험을 바탕으로 비전·통신·PLC·전기 I/O·기계 구동부를 개별 요소가 아닌 하나의 자동화 시스템으로 바라보고, 각 단계의 신호 흐름을 확인하며 문제를 해결하는 역량을 쌓았습니다.
